# Drop Menu Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A new setting, "Dropping a task into a bucket: Pin / Ask for a date". With Ask, dropping a task into a bucket that has a date range opens a menu offering to pin it there or to give it a date from that bucket's range.

**Architecture:**
- A pure module, `src/core/DropDates.ts`, decides whether a drop asks, which date field it writes, and which days it offers.
- `GTDPanel.svelte` shows the menu (Obsidian `Menu`) between the drop and the existing move flow.
- A date pick goes through a new `GtdPanelView.handleDropDate`, which writes the date, unpins, and saves the drop position in one render, the way `handleMove` does.

**Tech Stack:** TypeScript, Svelte 5 (legacy syntax), Obsidian API, Jest, the ObsidianE2EHarness specs.

**Spec:** this plan carries its own. The brainstorm it comes from (`docs/superpowers/specs/2026-11-11-plan-mode-brainstorm.md`, section "Pins vs dates: the drop menu") lives only on the local branch `temp/plan-mode-design`. It is quoted in full here, so nothing else needs reading.

> - New setting: **"Dropping a task into a bucket: Pin / Ask for a date".** The requester (pins only, `#gtd/` tags, no dates) uses Pin. A **pin icon next to undo/redo** switches it on the fly. *(That icon belongs to plan mode's toolbar, not this plan.)*
> - **Ask:** dropping into a bucket with a date range opens a menu:
>   - "Pin to <bucket>"
>   - up to 7 dates from that range: start, 2nd day, 25%, middle, 75%, 2nd-last day, end
>   - Custom…, which opens Kalendae limited to the bucket's range
> - The date is written to the field set by the Auto-assignment date setting (see `src/core/PlanningDate.ts`).
> - A bucket with no date range (Someday, tag-only buckets): pin, no menu.
> - No menu when reordering inside the same bucket.
> - Escape / clicking outside the menu cancels the drop; the task goes back.
> - Never ask anything on Apply.
> - **Ships first in the normal panel, as its own release**, ahead of plan mode.
> - Related TODOs: GTD TODO #41 (Custom… without Kalendae offers to install it), Kalendae TODO #29 (`pickDate` accepts a list of allowed ranges and single days).

## Decisions this plan makes that the spec leaves open

Vitaly reviews these with the plan. Each is a one-line change if he wants it otherwise.

1. **The default is Pin.** Existing installs keep today's behaviour.
2. **A bucket's range is its effective one.** These are the days on which auto-placement would actually put a task there. A task goes to the *first* bucket whose rule matches (`autoAssign` in `BucketManager.ts`), so This Month's range excludes the days This Week already takes. The range starts today. Days are counted up to 366 days ahead. If the bucket still matches on the last day counted, it has no end, so it counts as having no date range: catch-all, `beyond-days`, and a rule shadowed to nothing all pin without a menu.
3. **Which field:** the task's current planning date field (`planningDate(task, planBy).source`). If the task has none, it's `due` for `due-only` and `due-first`, and `scheduled` for every other mode, which is the same rule `dateEntries` in `DateMenu.ts` uses for "Set … date". With Plan by = `manual`, dates don't place tasks, so a drop always pins without a menu.
4. **Only days that really land the task in the target bucket are offered.** Each candidate day is checked by placing the task with that date. Under `earliest`, re-dating one field can let the other date win; such days are left out. If none are left, the drop pins without a menu.
5. **A date pick always unpins**, since a pin would override the date.
6. **Menu rows** use the same two columns as the row menu's presets:
   - left: "Today", "Tomorrow", or "In N days" (with the existing `formatDate` day on the right, e.g. "Sun, 18 Oct")
   - repeated positions collapse, so a one-day bucket like Today offers a single date.
7. **Custom… shows only when Kalendae is available**, as in the row menu.
   - It opens on the range's first day and passes the range as `allowed`. Kalendae ignores that until its TODO #29 lands.
   - A day outside the range is still written, and the task goes wherever that date puts it.
   - The install offer for when Kalendae is missing is GTD TODO #41, a separate feature after this one.
8. **Only drag-and-drop asks.** The quick-move buttons and the row menu's "Move to" still pin.
9. **A parent with pinned children:** after a date pick, the existing "move the children too?" dialog still shows. "Move all" pins the children to the target bucket, as it does today.

## Changes after manual QA

Vitaly's QA (2026-11-12 to 2026-11-14) changed these, and the code follows them, not the tasks below.

1. **Which days.** A range of up to 7 days offers every day. 8 days offer 5, 9 offer 6, and 10 or more the seven positions. A menu never leaves out exactly one or two days, since that reads as a bug.
2. **Custom…** shows only when the menu leaves out some day of the range (`offersCustom`).
3. **A Custom… day outside the bucket** is rejected with a notice, and nothing is written. This replaces Decision 7's second bullet.
4. **While the menu is open**, a copy of the row shows at the drop position and the real row is hidden. On a collapsed header, the row is hidden and the header keeps its drop outline. The copy waits for the move-children dialog, if one opens.
5. **Closing the menu.** Escape cancels, and the task goes back. Any other close, such as a click elsewhere, pins the task and says so in a notice. This replaces "Cancel" in Task 4.
6. **Collapsed header drops.** On its way to a collapsed header, a drag can cross an open bucket or its own siblings. SortableJS then also reports a drop or a reorder there. The header's drop now counts alone (`headerDrop` in `dragState.ts`). While a header is the target, SortableJS's placeholder is hidden.

## Review Focus

1. **Escape after a cross-bucket drop.** The row must be back in its original slot, and stay there through later renders. `BucketGroup.svelte`'s `onAdd` already puts the DOM node back before dispatching, so cancelling must do nothing else. Pinned by e2e case 4 (Task 5). Watch for the stranded-row trap: reload the panel before re-testing a drag fix.
2. **Overlapping rules.** Dropping into This Month must never offer a day that lands in This Week. Pinned by `effectiveRange excludes days an earlier bucket takes` (Task 1).
3. **A pinned task dropped with a date.** The pin is removed in the same write, or the tag keeps it where it was. Pinned by e2e case 2 (Task 5).
4. **Drop position kept.** A dated drop between two tasks shows there after the write, not at the bucket's end. Pinned by e2e case 2's order assertion (Task 5).
5. **Plan by = manual, or a task already closed.** No menu, and a plain pin. Pinned by `dropDateOptions is null under manual` (Task 1).

- Produces:

```ts
export const RANGE_HORIZON_DAYS = 366;
/** Every day from `now` on that auto-placement gives to this bucket, or null when the range has no end. */
export function effectiveRange(bucketId: string, buckets: BucketConfig[], now: Date, weekStart: WeekStart): Date[] | null;
/** The spec's seven positions over `days`, by index, without repeats, in order. */
export function pickDays(days: Date[]): Date[];
export interface DropDateOptions {
  field: DateField;
  /** YYYY-MM-DD, each checked to land the task in the target bucket. */
  days: string[];
  /** For Custom…: the range's first and last day, YYYY-MM-DD. */
  range: { from: string; to: string };
}
/** Null means: pin, no menu. */
export function dropDateOptions(task: TaskRecord, targetBucketId: string, settings: PluginSettings, now: Date): DropDateOptions | null;
```

Positions in `pickDays`, with `n = days.length` and `last = n - 1`: the indices `0, 1, round(last * 0.25), round(last * 0.5), round(last * 0.75), last - 1, last`, clamped to `[0, last]`, with repeats removed, in ascending order.

`dropDateOptions` returns null when:
- `settings.planBy === "manual"`
- the task's status is not open (`" "`) or in progress (`"/"`)
- `targetBucketId` is To Review
- `effectiveRange` is null or empty
- no picked day survives the landing check

The landing check is `autoBucketFor(parseFile(task.filePath, setDateLine(task.rawLine, field, day, true, settings))[0], settings, now)?.id === targetBucketId`.

### Task 4: The drop menu and the dated drop

**Files:**
- Modify: `src/main.ts` (`GtdPanelView`: new `handleDropDate` beside `handleMove` ~659; `mountSvelte` props ~599)
- Modify: `src/views/GTDPanel.svelte` (`handleDrop` ~425, `handleMove` ~166, `confirmMoveChildren` ~191, pointer tracking beside `panelDragOver` ~376)

**Interfaces:**
- Consumes: `dropDateOptions`, `DropDateOptions` (Task 1); `dropIntoBucket` (Task 2); `DatePicker` with `allowed` (Task 3).
- Produces:
  - `GtdPanelView.handleDropDate(task: TaskRecord, field: DateField, date: string, targetBucketId: string, orderedTaskIds: string[] | null): Promise<void>`, a public method (e2e calls it), passed to the panel as prop `onDropDate` with the same signature. It mirrors `handleMove`'s single-render sequence:
    1. `replaceTaskLine(app, task, (line) => [setDateLine(line, field, date, true, settings)])`. On failure: notice `notices.dateFailed`, `reindexFile`, return.
    2. `diffForEdit(...)` → `plugin.recordTaskDiff`, as `settleLineWrite` does.
    3. `reindexFileSilently(task.filePath)`.
    4. Recompute order keys. `purgeOrderEntry` the task's entry. When `orderedTaskIds` is set, `taskOrder[targetBucketId] = mapToOrderEntries(orderedTaskIds, keys)`.
    5. `saveSettings()`, which is the one render.

GTDPanel flow:
- **Pointer:** a capture-phase `dragover` and `pointermove` listener on the panel root records `lastDropPoint = { x: clientX, y: clientY }`, beside the existing `panelDragOver`.
- **`handleDrop`:** after finding the task, it only shows the menu when `settings.dropIntoBucket === "ask"`, the source and target buckets differ, and `dropDateOptions(task, targetBucketId, settings, today())` is non-null. Otherwise it goes straight to `handleMove` as today. The header drop on a collapsed bucket passes `orderedTaskIds: null` and goes through the same path.
- **Menu**, `new Menu()` shown with `showAtPosition(lastDropPoint)`:
  1. `t("panel.dropMenu.pinTo", { name: "<emoji> <name>" })`, icon `pin`, which calls `handleMove(task, target, orderedTaskIds)`, the existing path with the children dialog.
  2. A separator.
  3. One row per `options.days`, built like the row menu's preset rows: `gtd-date-row` with step and day spans. The step reads `t("panel.dropMenu.today")`, `t("panel.dropMenu.tomorrow")`, or `t("panel.dropMenu.inDays", { count })`; the day is `formatDate`. A row calls `dropWithDate(task, options.field, day, target, orderedTaskIds)`.
  4. When `getDatePicker()` is non-null: `t("panel.contextMenu.customDate")`. It opens the picker with value `options.range.from`, anchor = the target bucket's element (`.gtd-bucket[data-bucket-id=…]`) or the drop point's `MouseEvent`, and `allowed: [options.range]`. A picked day calls `dropWithDate`.
- **Cancel:** set a local `chosen = true` in every item's `onClick`. `menu.onHide(() => { if (!chosen) … })` does nothing else, because the DOM was already put back in `onAdd`. No write, no reorder.
- **`dropWithDate`:** reuses the children check from `handleMove`. If explicit children sit in another bucket, set `pendingMoveConfirm` with a new optional `date: { field, day }`. Otherwise call `onDropDate`.
- **`confirmMoveChildren`:** with `date` set, it calls `onDropDate` for the parent and then, when moving the children, the existing `onMove(child, target)` for each.

Strings, under `panel.dropMenu`, each with a `_comment`:
- `pinTo` "Pin to {{name}}"
- `today` "Today"
- `tomorrow` "Tomorrow"
- `inDays` "In {{count}} days", with `inDays_one` "In 1 day"
